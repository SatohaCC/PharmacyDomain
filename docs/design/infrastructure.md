# 永続化とDI

InfrastructureはDomain・ApplicationのProtocolに具象アダプタを接続します。
HTTPからDBやトランザクションを直接操作せず、具象生成はDI・bootstrapへ集めます。

## 集約のマッピング

JSONB payloadを集約の保存値の正とし、検索・一意制約に必要な値だけを列へ複製します。
列の導出は共通マッピングへ一度だけ定義し、書込みと復元時の一致確認の両方に使います。
payloadと列が食い違うデータの復元は拒否します。集約の読み書きはRepository基底を通し、世代記録やupsertを各Repositoryへ分散させません。

共通接続・スキーマ・codec・基底は共通postgresへ、集約別Repositoryは各コンテキストへ置きます。
Repositoryは1集約1ファイルとし、外部取得・DI・HTTPへの依存をcodecや永続化へ混ぜません。

## トランザクションとDB制約

保存はINSERTと競合時更新を1文で行い、読取世代と一致した行だけを更新します。
世代不一致は競合として拒否し、UoWが世代をトランザクション単位で追跡します。commitされなかった正常終了も明示的にrollbackします。
AsyncSessionは並行実行で使い回さず、スコープごとに組み立てます。複数集約の進行とGuardは[Application](application.md#保存前guardとトランザクション)が所有します。

期間重複はdaterangeとgist排他制約で守り、終了日を含む期間は閉区間として表します。
任意コードの一意性はNULLを除く部分インデックスを使い、無効行のキー再利用可否は集約ごとに決めます。
NULLを含む組の同一性には非NULLの比較キーを用意します。制約名や競合時の挙動は実ドライバ・実DBで検証します。

過去のmigrationテストへ最新マッピングを無条件に渡さず、そのリビジョンに存在した列だけでデータを投入します。
シードは外部キーの参照先から保存します。DDLと保存列の整合はDBなしでも検査し、サーバー挙動は[結合テスト](../development.md#実postgresqlの結合テスト)で分けて確認します。

## 配線

ユースケースの生成は責務別の束へまとめ、Application所有の登録情報・実行Protocolへ接続します。
束はアクセス時に組み立て、同一スコープ内でキャッシュします。HTTPへ具象DIを公開しません。
