# Domainの設計

Domainは業務上の事実・不変条件・状態遷移を所有します。HTTP・DB・Applicationに依存せず、
構築・変更できたモデルが有効な状態であることを保証します。業務範囲は[設計概要](../README.md)を参照します。

## コンテキスト境界

他集約は所有元の公開IDだけで参照し、Entity・Protocol・例外・Serviceを直接持ち込みません。
必要な外部情報はApplicationが利用側所有の不変値へ変換し、Domainが業務判断を行います。
単一集約で保証できる規則をDomain Serviceへ重複させず、複数集約にまたがる判定だけを無状態のServiceへ置きます。

Coverageは資格台帳・有効性・適用組み合わせ・適用時点の固定値と選択履歴を所有します。
Receptionは外部受付原本・訂正履歴・受付判断を所有し、受信した保険情報から資格登録や適用選択を自動実行しません。
元資格IDと適用固定値は同じ枠で保持し、公費順位の判定もCoverageへ集約します。

foundationは標準ライブラリだけ、sharedは標準ライブラリとfoundationへ依存します。
Shared Kernelに置くのは所有者のいない語彙と合意した共有規則です。複数箇所で使うという理由で
薬品マスタ・処方原本などに所有者のある語彙を移しません。Application共通処理もShared Kernelとは区別します。

## 値・Entity・Repository

- Primitiveが単一値の正規化と検証を完了し、フィールドには意味のある具象型を使う。用量はDecimalで表す。
- Entityと集約は不変とし、状態変更は新しいインスタンスを返す。構築後の置換による暗黙変換を行わない。
- 集約固有の複合値・子Entityと、独立したPrimitive・Value Objectを区別する。
- RepositoryはDomainのProtocol。一意性・期間競合の最終防衛は保存時の原子的な契約とし、事前readだけに依存しない。

配置は識別子・例外・Primitive、複合値、Entity、Repository抽象、Serviceの役割へ揃え、内側へ依存させます。
現在のファイル名・型構造と許可依存はコードと検査設定を正とします。

## 時間とライフサイクル

ライフサイクルは、無効化なし・現在の有効フラグ・状態列挙・日付付き有効化を使い分けます。
無効化後の一意キー再利用可否は別の判断であり、患者外部IDとスタッフコードを同じ規則へ揃えません。
子レコードの有効性を期間から導出できる場合、重複した真偽値を持たせません。

終了日を含む制度期間と、無効化発効日を含まない有効化期間を区別します。
スタッフは店舗を問わない主所属期間の重複と、同一店舗の所属期間の重複を別に防ぎます。
退職は所属履歴を打ち切り、退職後の配属予約が残る場合は拒否します。再有効化で所属は復元しません。

## 参照データと時間

MedicineCatalogは非テナントの版付き参照データです。処理時点の「今」ではなく、処方箋交付日など
業務上の対象時点で引きます。マスタは生の事実を持ち、規制区分等の判定材料への変換はアダプタが担当します。
判定不能を「非該当」へ倒さず、危険な処方の判断はfail-closedにします。
