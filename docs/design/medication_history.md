# 薬歴と臨床プロファイル

MedicationHistoryはEventに結び付く薬剤師記録と、そこから再構築する臨床プロファイルを所有します。
[業務機会](care_event.md)と、[患者の自由記載](patient.md#自由記載の頭書き)は別の責務です。

## 原記録と訂正

薬歴はSOAP、指導者・指導日時、レビュー・確定監査、臨床プロファイルへの差分を持つ真の記録です。
法人ごとの記載区分はEvent種別によらず共通に検証します。下書きでは途中入力を許し、白紙確定は拒否します。
調剤録検索用に持つ調剤IDの写しは、対応Eventとの一致を保存境界で確認します。

SOAPの修正は追記として元の記載を残します。指導者・指導日時・臨床差分等の事実訂正も、
対象・操作・前後値・理由・訂正者・記録時刻を別の履歴として追記し、原本や確定監査値を上書きしません。
確定・移行記録にだけ事実訂正を許し、下書きは下書き編集を使います。
配列要素には安定した識別を持たせ、同名の別要素を巻き込まずに置換・取消しできるようにします。

原本・SOAP追記・事実訂正を再生して有効な値を求め、必須区分の検証も訂正後の値で行います。
受付・NSIPSの原データは訂正しません。移行記録へ存在しない監査値を補わない方針は[CareEvent](care_event.md#発生日時登録日時指導日時)を参照します。
処方医へのトレーシングレポートと返答は該当薬歴へ帰属させます。
Uファイル再取込の加算比較は処方箋受付Eventに結び付く薬歴だけを対象とし、相談等へ調剤由来の識別子を要求しません。

## 臨床プロファイルの投影

アレルギー・副作用・既往歴・併用薬・生活像等の現在像は、薬歴の有効な差分から投影します。
追加だけでなく誤登録取消や疾患状態変更も差分に含めます。直接編集する別の真実を持たせません。

同一法人・患者の投影対象記録を有効な指導日時順に再生し、同時刻は確定日時・登録日時・IDで順序を決めます。
日時のない下書きはタイムライン末尾に置きます。由来となる薬歴IDと既存の投影IDを維持し、
指導者・日時・差分の訂正を投影の内容と順序へ反映します。

原記録を先に保存し、同じUnitOfWorkで投影を保存します。訂正時も患者全体の対象記録から再生します。
再構築は回復策であり、原子性の代替ではありません。Event作成と薬歴確定・訂正の店舗業務条件は[店舗設計](store.md)を参照します。

## 調剤録の記載事項と資料の解釈

| 根拠 | 扱う範囲 |
| --- | --- |
| 薬剤師法第25条の2 | 服薬状況把握、情報提供、指導 |
| 薬剤師法第28条・施行規則第16条 | 調剤録の記載事項と保存 |
| 保険薬局及び保険薬剤師療養担当規則第10条 | 保険調剤録 |
| 保険調剤の理解のために 令和8年度 | 薬剤服用歴等の記載事項 |

電子処方箋の調剤編はSOAPの根拠資料として使いません。
調剤録の記載事項は調剤・処方箋・患者等に分かれるため、不変な参照情報を受け取り、号ごとの充足を3値で報告します。
薬歴未確定・調剤未完了は記載事項とは別の軸です。関連処方・調剤のない相談Eventを調剤録の代替とは扱いません。

記載事項の不足は報告にとどめ、薬歴確定を止めません。薬歴として記録を残すことと、
法定調剤録の代替として十分であることを分けるためです。保険調剤録の保険固有項目はこの判定の対象外です。

## 未解決事項

法定の3年保存を保証する運用が残ります。記載充足の判定だけで保存・監査運用まで保証したとは扱いません。
資料の所在は[一次資料](../references/README.md)、採否と移行の経緯は[設計判断](../decisions.md)を参照します。
