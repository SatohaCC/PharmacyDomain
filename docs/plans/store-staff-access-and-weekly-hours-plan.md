# ログイン情報と店舗別の所属・週勤務時間の実装計画

作成日: 2026-11-02

状態: 2026-11-02に実装計画と別紙テスト仕様の承認を受けて実装。ログインID・任意メール・店舗別操作ロール・適用日付き週勤務時間と履歴を追加した。

## 目的と合意した範囲

個人メールを持たないスタッフがログインIDとパスワードで利用できるようにする。
同じスタッフが複数店舗に所属し、それぞれに異なる操作権限と週当たり勤務時間数を設定できるようにする。
薬剤師等の店舗での従事状況を扱うため、業務上の立場とシステム操作権限を別の事実として保持する。

例: A店では薬剤師として週32時間・編集可能、B店では薬剤師として週8時間・閲覧のみ。

曜日別の勤務時間帯・日付別シフト・勤怠実績・行政への電子申請は今回の対象外とする。
店舗自身の曜日別営業時間は既存の別機能である。週勤務時間数を理由に時間外ログイン制限を追加しない。

## 根拠と適用範囲

さいたま市の[週当たり勤務時間数の変更](https://www.city.saitama.lg.jp/005/001/013/016/p014658.html)では、資格者全員の変更前後の氏名・勤務時間数、体制を示す書類、ローテーション表が案内されている。
[埼玉県の変更届案内](https://www.pref.saitama.lg.jp/a0707/yakkyoku-iyakuhinhanbai/henko.html)では施設所在地を管轄する保健所への届出を案内している。
確認日はいずれも2026-11-02。自治体ごとの様式や必要書類が同一であるとは扱わない。

本機能は届出準備のための店舗別の事実と変更履歴を管理する。週時間数の登録だけをもって届出完了・体制要件適合とは表示しない。
提出状態・提出日・受付番号や帳票生成は別途要件が確定した場合に追加する。

## 所有する事実

| 所有先 | 事実・判断 |
| --- | --- |
| Identity | ログインID、パスワード、任意の連絡先メール、法人管理権限、店舗ごとの操作権限と利用停止 |
| Staff | 店舗への所属期間、店舗別の週勤務時間数とその適用履歴、資格と整合する従事区分 |
| Store | 管理薬剤師の期間付き任命、店舗の営業時間・許認可・運営状態 |
| Application | 選択店舗での権限解決、所属・資格・任命との照合、履歴更新と保存の原子性 |

Staff全体の雇用契約上の週所定労働時間は既存の意味を維持する。
それを各店舗へ複製したり、所属店舗数で均等配分したりしない。
管理薬剤師の立場はStoreの任命から対象日について解決し、別の自由入力項目へ複写しない。
薬剤師・登録販売者等の従事区分は資格と整合させる。閲覧・編集権限だけで資格を付与しない。

## 新しい契約

### ログイン

- ログインIDとパスワードを必須、連絡先メールを任意とする。未指定・空欄のメールは未登録として保存する。
- 法人利用者のIDは法人内で、運営者のIDは運営者全体で一意とする。
- ログインIDは3～64文字、半角英数字・ピリオド・ハイフン・下線、先頭は英数字とする。前後空白を除去して小文字へ正規化する。
- 連絡先メールは指定された場合だけメール形式を検証し、ログイン照合には使わない。同じ連絡先メールを使うことを妨げない。
- 初期管理者登録、スタッフの資格情報発行、法人・運営者ログイン、初期運営者発行コマンドを同じ契約へ揃える。
- 既存の初回パスワード変更、試行回数制限、セッション失効と秘密の非表示を維持する。

### 店舗ごとの操作権限

- 法人管理権限と店舗利用権限を分離する。店舗には閲覧・編集の操作ロールを設定する。
- 同じスタッフでもA店とB店で異なるロールにできる。店舗ごとの停止も独立させる。
- 選択店舗の現在の権限だけで店舗業務を認可する。法人管理者であることから全店舗の業務編集権限を自動付与しない。
- 管理薬剤師の店舗管理権限は既存の有効任命から加算し、他店舗へ波及させない。管理薬剤師の任命・専任性の規則は今回緩和しない。
- 店舗選択時・各リクエスト・保存直前の再検証とSQL読取範囲を揃える。別店舗のロールを引き継がない。
- 法人管理者は自法人、管理薬剤師は現在の管理対象店舗の許可された範囲だけを変更できる。最後の有効法人管理者の保護も維持する。

### 店舗ごとの週勤務時間と履歴

- 所属に紐づく勤務条件履歴として、週当たり勤務時間数・従事区分・適用期間を持つ。
- 時間数はDecimalで表現し、0～168時間、0.01時間単位とする。この上限は一週間の長さによる入力検証であり、労働法上の適法性の判定ではない。
- 未登録と明示的な0時間を区別する。既存データの欠落を0で補完しない。
- 現在値と対象日での照会、適用開始日の指定、変更前後の確認を提供する。同じ所属内の勤務条件の適用期間は重複させない。
- 既存所属と同じく期間の終了日を含む。変更日から新条件を適用し、旧条件はその前日で終了する。同日開始の訂正は履歴を消さず訂正として記録する。
- 勤務条件の適用期間は所属期間内に収める。退職・所属終了と将来予約の整合を既存ルールに合わせる。
- 過去の条件を上書きせず、誰がいつ変更・訂正したかを追跡できるようにする。
- 店舗の所属者一覧から資格者の変更前後を確認できるようにする。画面へ登録したことと行政へ届け出たことを分ける。

## 実装の順序

1. Identity/Staff/Storeのモデルと不変条件、ログインIDと週勤務時間のPrimitive、Domainテストを追加する。
2. 認証資格情報のIDとメールを分離し、法人権限と店舗別操作権限を分ける。Staffの勤務条件履歴を永続化し、DB制約・Repositoryの原子性を実DBで確認する。
3. 登録・変更・対象日照会UseCaseと保存前Guardを実装する。横断更新は同じUoWと既存の法人ロックで行い、取得後に再確認する。
4. 認証・契約登録・店舗権限・スタッフ所属のHTTP入出力を変更し、OpenAPI型を再生成する。
5. ログイン・登録画面を変更し、スタッフ詳細の所属店舗ごとに従事区分・週時間数・適用日・操作権限を表示・編集できるようにする。管理薬剤師の任命は既存の専用操作へ接続する。
6. 初期発行・シード・通常文書を新契約へ揃え、別紙のテストと標準ゲートを実行する。Dockerにも反映して操作経路を確認する。

Domain間の接続には公開IDと利用側所有の境界値を使う。Command/Queryを分離し、HTTPのPrimitive変換とドメイン判断を混ぜない。

## 既存データの移行

- migration適用前に専用DBでリハーサルし、開発DBのバックアップと対象件数の確認を行う。
- 旧メールを新しいIDだと仮定しない。新IDの明示的な対応表を用意し、未割当・正規化後重複があれば移行を拒否する。既存のメールは連絡先として保持する。
- 法人共通だった旧店舗ロールは、その時点で許可済みの各店舗へ移す。法人管理権限を店舗権限へ暗黙に変換しない。
- 店舗別の勤務時間は元データがないため未登録とする。勤務履歴を過去へ捏造しない。
- アカウント・本人・スタッフ・任命・監査のIDと対応を保持する。資格情報や履歴を削除して作り直さない。
- 新契約へ切替後は旧emailログインAPI・法人共通店舗ロールの互換分岐を残さない。既存セッションは失効して再ログインを求める。

## 実装前の確認対象

時間数の精度・未登録状態・履歴と訂正の扱い、移行時のログインID対応表を含む本計画と、[別紙テスト仕様](store-staff-access-and-weekly-hours-tests.md)を確認する。
対象自治体の帳票の完全再現や提出機能は追加承認された範囲に限る。


## 2026-11-03の操作導線の補完

利用者から「所属を選ぶ→各店舗の権限を選ぶ→各店舗の勤務時間を選ぶ」という流れの指定を受け、登録と詳細編集を揃えた。
選択していない店舗の権限・時間数の入力欄は表示せず、選択済み店舗だけを同じフォームで設定する。

新規登録は主所属・兼務所属・操作権限・週勤務時間・従事区分を一つの要求で保存する。
既存ユーザーの編集はIdentityの変更処理から勤務条件更新の境界へ接続し、同じ法人ロックとUoWの下で権限・所属追加・勤務条件を保存する。
いずれかの条件が不正なら全体を取り消す。変更のない勤務条件を再送した場合は履歴を増やさない。

詳細画面は全選択店舗の操作権限・照会日時点の週時間数・従事区分を並べ、過去の勤務条件は履歴欄で確認する。
店舗の選択解除は利用権限の解除を意味し、勤務所属の終了や管理薬剤師の任命終了を暗黙に行わない。この違いを編集画面に明示する。


### 店舗ごとの所属開始日と入力単位

2026-11-03の追加指示を受け、所属開始日を全店舗共通とする入力を廃止した。
一店舗ごとに所属開始日・操作権限・週勤務時間・従事区分を一つの欄にまとめる。
新規登録の主所属開始日は主所属店舗の入力から取り、各兼務所属にはそれぞれ指定された日付を使う。
勤務条件の初回適用日もその店舗の所属開始日とする。他店舗の日付で補完しない。
既存所属の開始日は履歴を保つため参照表示とし、その後の勤務条件変更の適用開始日は店舗ごとに指定する。


### 店舗別週勤務時間の合計上限

2026-11-03の追加指示に基づき、同時期に有効な店舗別勤務時間の合計が週所定労働時間を超える登録・変更を拒否する。
所属期間、適用日、同日訂正、将来予約を考慮し、現在以降の適用境界でDecimalの合計を比較する。
複数店舗の配分をまとめて変更するときは、変更途中ではなく全変更後で検証する。契約時間の引下げ時も再検証する。
過去の記録を現在の契約時間に合わせて書き換えない。労働契約変更と勤務条件変更は同じ法人ロックで直列化する。

利用者の指定により、週所定労働時間が未登録でも保存を許可し「上限未確認」と表示する。
店舗別時間数が未登録の場合も値を捏造せず、登録済み分の合計と未登録の存在を分けて表示する。
