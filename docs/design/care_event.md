# 業務イベントと薬歴の分離

CareEventは患者に対する業務機会の発生と種別を所有し、SOAP等の薬剤師記載はMedicationHistoryが所有します。
受付・フォローアップ・相談・訪問などを表し、薬歴なしでもEventを登録できます。

## 関係と種別

Eventに対する薬歴は0件または1件とします。受付・処方箋・調剤・関連元Eventは実際に存在する場合だけ参照し、
相談等のために架空の処方・調剤IDを作りません。種別は標準と法人独自に分け、標準種別の改名・無効化は認めません。
Eventには作成時の種別名を残し、後から定義を改名しても過去の表示を変えません。

関連元Eventの法人・患者一致、標準または自法人の種別だけを使えること、受付との一意な関連を保存境界でも守ります。
関連候補として返すのは同一法人・患者の最小限のメタデータだけで、別店舗のSOAP本文の読取範囲を広げません。

## 発生日時・登録日時・指導日時

新規Eventの発生日時、注入時計による登録日時、薬歴の指導日時は別の事実です。
NSIPS受信時刻を実施日時として使わず、Eventの発生日時で薬歴の指導日時を補いません。

旧記録から発生日時や独立した確定監査値を特定できない場合も、推測して通常の確定記録に見せません。
時刻不明Eventと移行記録を区別し、時刻不明の下書きを確定する際は利用者が確認した発生日時を一度だけ設定します。
旧ID・payload・対応関係の保全は[判断記録のADR-61](../history/decisions.md#adr-61-業務イベントと薬歴記載を分離し時刻不明の旧記録を明示する)を参照します。

## 店舗業務との関係

Event作成は新規業務です。過去の発生日時を入力しても、店舗状態と管理薬剤師在任は作成時点の業務日で判定します。
種別管理とEvent利用の権限、店舗読取範囲は[Application設計](application.md)へ接続します。
