# 範囲付きユーザー権限の変更計画

状態: 方針承認済み。実装・検証完了。

## 合意した境界

本人に、一般ユーザー・管理薬剤師・法人管理者の権限を範囲付きで加算する。
一般ユーザーの権限は店舗単位、法人管理者の権限は自法人単位とする。
管理薬剤師の管理権限は、その日の有効な確定任命から付与する。
既存の業務操作・閲覧の区別は一般ユーザー権限の内訳として維持する。

法人管理者にも店舗利用権限を追加できる。管理薬剤師は、複数店舗利用者や法人管理者についても、自店舗分の利用権限だけを編集できる。
法人管理者としての権限、他店舗の利用範囲、アカウント全体の状態を管理薬剤師から変更することは禁止する。
有効な管理薬剤師本人の店舗権限は法人管理者が管理する。

店舗の利用停止・再開は、他店舗の利用と法人管理権限を維持する。
アカウント全体の停止は、自法人の法人管理者とベンダーシステム管理者が行う。
最後の有効な法人管理者を失う変更は拒否し、他法人の存在は404で隠す。
アカウント全体の再開権限は今回変更しない。

管理薬剤師は在任期間中、一店舗だけに勤務・所属できる。
任命の追加とスタッフの所属変更の双方で期間の重なりを検証し、利用店舗を追加する経路でも一店舗への限定を検証する。
任命と権限変更は同じ法人ロックを使い、失効した任命による更新は拒否する。

## 実装と検証

現在の本人・法人アクセス権・期間付き任命を使い、独立した店舗管理者の固定ロールは保存しない。
更新処理では認証時の権限だけに依存せず、現在の任命と本人・所属・アカウント状態を再確認する。
SQLでも自法人かつ担当店舗を利用する対象に絞り、参照後の絞り込みだけで保護しない。
現在のHTTP更新窓口に店舗指定と店舗利用状態を追加し、同等の操作窓口は増やさない。
本人の権限一覧には三種類の権限とそれぞれの範囲を返す。

既存のユーザー登録画面では、法人管理者にも店舗利用範囲と対応スタッフを指定できるようにする。
ユーザー編集画面の新設は今回の範囲に含めず、店舗単位の編集は既存のHTTP APIで提供する。

Domain・Application・HTTP・実PostgreSQLのテストで、期間境界、複数店舗、法人管理権限の維持、越境、権限失効、保存前検査、停止後の認証拒否を検証する。
既存の開発DBを初期化せず、この作業専用の新規コンテナと空DBで結合テストを実行する。
