# ローカル認証の利用開始

本番の起動点 `app.main:app` はログインID・パスワード方式を使う。ベンダーは「法人を登録」から法人と初期管理者を一括登録し、ログインIDと初期パスワードを本人へ渡す。メールアドレスと招待受諾は不要である。代表者と初期管理者は別の人として入力できる。

## 初期設定

先にDBマイグレーションを適用する。開発用Composeの場合はリポジトリルートから実行する。

```powershell
pnpm db:up
pnpm db:migrate
```

最初のベンダーアカウントは、DBへ接続できる運用者が対話式で発行する。既存の開発DBではシード済みの固定トークンも引き続き使える。本番の起動点は固定トークンを受け付けない。

```powershell
# ローカル実行時は、接続するDBのDATABASE_URLを環境変数へ明示設定する。
pnpm --filter pharmacydomain-api exec uv run python -m tools.provision_vendor --login-id vendor-admin --last-name 運用 --first-name 管理者 --last-name-kana ウンヨウ --first-name-kana カンリシャ
```

パスワードは端末の非表示入力で2回確認する。コマンド引数、`.env`、ログへ記載しない。このコマンドは新しい本人とベンダーアカウントを作り、同一ログインIDでの再発行を拒否する。初期ベンダーも初回ログイン時の変更が必要である。

## 契約と利用開始

1. ベンダーがログインし、法人名・代表者・初期管理者・ログインID・初期パスワードを入力する。
2. 全項目の保存が成功すると法人と管理者の登録が完了する。ログインIDの重複などで失敗した場合、法人だけが残ることはない。
3. 管理者へログインIDと初期パスワードを安全な方法で渡す。パスワードの再表示・再取得はできない。
4. 管理者は初回ログインで自身の新しいパスワードを設定し、利用を開始する。

ログインIDは3～64文字の半角英数字・ピリオド・ハイフン・下線で、先頭は英数字とする。前後の空白を除き、小文字へ正規化する。パスワードは15～128文字で、空白を含めて入力どおりに照合する。

変更専用セッションの期限は10分、通常セッションは8時間である。期限切れやブラウザの再読込後は再ログインする。トークンはブラウザのメモリにだけ保持し、URLや永続ストレージへ書かない。ログアウトではサーバー上のセッションも削除する。

同じIDで5回連続して失敗すると15分間ログインを拒否する。未登録ID・パスワード不一致・ロック中の応答は共通にする。パスワード変更では以前の全セッションを失効する。業務要求のたびに現在のアカウントと法人権限を読み直すため、停止・権限変更は次の要求へ反映される。

既存の外部認証アカウントへログイン資格情報を自動付与しない。既存の本人・外部主体・招待履歴は保持する。パスワード忘れへの再発行フローは、この新規契約登録とは別の運用機能として扱う。
