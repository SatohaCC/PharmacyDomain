# アカウント停止権限の拡張計画

状態: 後続案に置き換え済み。以下は変更前の検討記録。

この案は、後続の合意による `scoped-user-permissions-plan.md` に置き換えた。以下は置き換え前の検討内容であり、現在の実装仕様ではない。

## 目的と権限

法人管理者は、自法人に所属するユーザーのアカウントを停止できる。
管理薬剤師は、現在の確定任命が有効な自店舗の一般ユーザーのアカウントを停止できる。
管理薬剤師の任命を店舗管理権限の根拠とし、独立した固定ロールは追加しない。
ベンダーシステム管理者の既存の停止権限は維持する。

一般ユーザーは店舗操作者・店舗閲覧者とする。管理薬剤師として有効な任命を持つユーザーと法人管理者は、管理薬剤師による停止の対象外とする。
他店舗にも利用権限を持つユーザーは、アカウント全体の停止によって他店舗の利用も止まるため、管理薬剤師からは停止できない。
所属のないアカウントや他法人のユーザーは法人・店舗管理権限から操作できず、存在を404で隠す。
法人アクセス権が停止中でも、自法人への所属が確認できるアカウントは対象に含める。
最後の有効な法人管理者を失う停止を禁止する既存の保証は維持する。

## 実装方針

- 既存のアカウント停止UseCaseとHTTP窓口を変更し、同等の別APIは増やさない。
- identity所有の参照契約を定義し、compositionで管理薬剤師の任命・本人との対応・対象の所属を接続する。identityからstoreの具象Applicationを呼ばない。
- 現在有効な任命は注入時計から得る業務日で評価する。任命の開始前・終了後・取消済みは権限を与えない。
- 認証済みActorの本人・法人と任命を照合する。HTTP入力から管理権限を生成しない。
- 対象アカウント・所属・任命の読取は、DBの取得条件でも対象法人と店舗を制限する。既存の店舗ロールの読取範囲を無条件に広げない。
- 所属が停止中の対象も判定できる参照を用意する。有効所属だけを返す既存検索を認可判定へ流用しない。
- 認可・最後の管理者の保護・保存を既存UoWと組織ロックの内側で行う。任命や所属の変更とのロック順序も整合させる。
- 再開権限の拡張や編集画面の新設はこの変更に含めない。

## テスト仕様

| 条件 | 期待結果 |
| --- | --- |
| ベンダー管理者が既存アカウントを停止 | 従来どおり成功 |
| 法人管理者が自法人の一般ユーザーを停止 | 成功、所属や本人対応は維持 |
| 法人管理者が他法人または所属なしのアカウントを指定 | 404、保存なし |
| 法人管理者が最後の有効管理者を停止 | 拒否、保存なし |
| 自店舗の有効な管理薬剤師が一般ユーザーを停止 | 成功 |
| 管理薬剤師の任命が開始前・終了後・取消済み | 拒否、保存なし |
| 管理薬剤師が他店舗・他法人・複数店舗利用者を停止 | 拒否、保存なし |
| 管理薬剤師が法人管理者・有効な管理薬剤師・自分を停止 | 拒否、保存なし |
| 一般ユーザーが他人または自分を停止 | 拒否、保存なし |
| 法人アクセス権停止中の自法人ユーザーを法人管理者が停止 | 成功 |
| DBの店舗読取範囲下で許可対象を停止 | 成功し、範囲外の存在は露出しない |
| 停止後に既存セッションで業務APIへアクセス | 既存の認証有効性判定で拒否 |
| 任命・所属変更または管理者停止が並行 | 境界・最後の管理者の保証を維持 |

ApplicationテストとHTTPテスト、実PostgreSQLの取得範囲・トランザクション・セッション結合テストで検証する。
完了条件はbackend全テスト、実DB結合テスト、strict mypy、Ruff、format、imports、Domain/Applicationハーネスの成功とする。
