# 担当者共通規約

feature-pipelineの担当者は初回にこの規約を読む。単独依頼では役割定義と指定範囲を使い、パイプラインの成果物や承認を前提にしない。

- 元の要件、ユーザーの追加指示、担当範囲、承認対象と版、指定ケース群・作業単位・方式・モードを確認する。必要な計画・仕様・対象範囲のAGENTS.mdと関連資料を読む。足りない文脈は進行役へ返し、承認を推測しない。
- 既存変更を保持し、役割の編集範囲を守る。PROGRESS_PATH・承認履歴・役割起動・次ケース・差し戻し回数は進行役が管理する。
- ブランチ・Worktree・コミット・PRはユーザーの明示依頼がある場合だけ扱う。reset・stash・cleanによる自動退避・破棄はしない。
- 読了済みで未変更の資料を毎回読み直さない。更新された契約や仕様は現在の版を確認する。調査済みの事実はファイル位置・根拠とともに利用し、不明な点や影響範囲を調べる。
- 検証は現在の差分に対応する証跡を利用できる。不足・変更後・懸念のある検証は実行する。環境不足、未実施、skip・xfailを成功としない。
- 結果は次の項目を短く返す。長いログは進行役指定の証跡先へ保存する。保存できない場合も重要な失敗・不足を省略しない。

```text
STATUS: 役割・モードに応じた結果
CASE/MODE: 対象ケース群・方式と段階（該当する場合）
CHANGES: 変更ファイル・理由・ケースと実テストの対応
CHECKS: 作業場所・コマンド・終了コード・件数・差分の版・証跡先
ISSUES: 失敗の原因・未実施・戻し先・残余リスク
```

失敗時は関連するアサーション・エラーと根拠を添える。PASSや完了報告はユーザーの承認ではない。次の役割を自分で起動しない。
